# HonorTransparentKeyboard（荣耀通透键盘）

针对百度输入法荣耀版的实验性 LSPosed/Xposed 模块。提供原生通透能力相关设置、按键/工具栏透明度与玻璃风格绘制，并在 v1.7 尝试移除手写书写区的白色提示底色。**不是百度、荣耀或 Apple 官方产品。**

## 当前状态与测试范围

- 源码版本 **1.7**，`versionCode 9`；包名 `local.honor.transparentkeyboard`。
- 仅针对 **百度输入法荣耀版 `com.baidu.input_hihonor` 8.2.510.383** 做过实机调试；不是百度输入法通用版插件。
- 测试环境为一套荣耀 MagicOS、可运行 LSPosed 的 Android 环境；未做跨系统、跨版本回归。构建声明 `minSdk 29` 不代表所有 Android 10 及以上系统都能使用全部效果。
- 本仓库首批只发布源码，**不附带 APK、第三方输入法安装包、反编译源码、设备备份或原始截图**。
- 代码仍包含诊断功能，未完成完整的安全审计。请先阅读下文“诊断与隐私”。

## 功能

- 调节背景通透程度、液态/磨砂材质、背景模糊、按键与顶部按钮透明度、玻璃强度。
- 顶部工具栏按钮按视觉中心缩小至原来的 80%；触摸区域不变。
- 玻璃高光/表面风格部分移植自 Kyant0/AndroidLiquidGlass（Backdrop），并作适配修改。**不是 iOS 26 原生渲染，也没有完整的光学折射效果**；模块不能直接采样其他 App 的底层画面，背景模糊依赖设备原生能力。
- v1.7 针对百度手写视图 `com.baidu.az.c.draw(Canvas)` 临时关闭其白色提示底色的绘制标志，绘制后恢复；不主动关闭手写或触摸功能，也不移除笔迹位图绘制。

### v1.7 白雾修复：证据与尚未验证项

诊断版观察到百度手写弹窗覆盖键盘上方区域，渲染白色透明度为 `56/255`；对应代码使用 `0x38FFFFFF` 绘制书写区底色。该路径属于输入法的手写层，而非模块的键盘染色或窗口变暗。

v1.7 加载后，日志确认修复钩子执行；随后若干次诊断渲染的手写弹窗透明度为 0。设置搜索页一次键盘展开/收起对比中，上方区域除光标闪烁外一致。

**限制：**上述 v1.7 抓图中手写弹窗仅覆盖键盘附近，尚未获得“同一 App、全屏手写层开启、修复前后”完整对照；未完成模块停用、模糊归零、原生设置、v1.6 四组严格同场景 A/B。保留手写笔迹的设计有代码依据，但没有完成全面的手写识别/笔迹回归测试。不要把这些观察理解为所有场景均已修复。

## 构建

原调试使用 JDK 21、Gradle 8.14.5、Android SDK Platform 35、Build Tools 35.0.1；Android Gradle Plugin 为 8.7.3。当前没有 Gradle Wrapper，需要自行准备 Gradle。依赖来自 Google、Maven Central 和 Xposed 仓库，首次构建通常需要网络。

1. 安装上述构建工具，并通过 `ANDROID_HOME` 或本地 `local.properties` 指向自己的 Android SDK；不要提交本机 SDK 路径或签名文件。
2. 在仓库根目录执行：

   ```sh
   gradle assembleDebug
   ```

3. 调试 APK 生成于 `build/outputs/apk/debug/`。构建输出、缓存及本地配置均不在发布白名单中。

默认构建使用 Android 调试签名，不是正式发布签名。不同电脑生成的调试证书通常不同；证书不一致时不能直接覆盖已安装版本。签名迁移与正式签名发布尚未配置；**不要分享调试或正式签名私钥**。

## 安装与 LSPosed 操作

以下仅适用于已经具备正常 Root/LSPosed 环境、并安装上述目标输入法版本的设备。本项目不提供 Root 或系统改造步骤。

1. 自行构建并安装模块 APK。
2. 在 LSPosed 启用该模块，将作用域设为 **百度输入法荣耀版 `com.baidu.input_hihonor`**；不要勾选无关应用或系统框架。
3. 按 LSPosed 提示完成加载。若需要重启目标进程，先保存正在输入的内容并收起键盘；不要在输入过程中强制重启输入法。不同环境是否需要重启系统，以自己的 LSPosed 提示为准。
4. 打开“荣耀通透键盘·全局”，使用预览输入框和各滑块。点击“确定修改”后查看连接/应用回执；必要时在输入内容已保存后使用“重启输入法”。
5. 异常时先在 LSPosed 停用本模块再重启目标输入法；不要先清除输入法数据，以免丢失词库或设置。

修改依赖特定版本的混淆类名、字段和系统私有能力。输入法或系统升级后可能无效、崩溃或产生视觉问题；请勿据此认为其他版本也兼容。

## 诊断与隐私（当前代码保留）

`FogProbe.java` 在目标输入法进程内观察窗口/弹窗和视图树，记录类名、资源标识、窗口标题、几何、背景属性与颜色统计，并在每个进程最多 8 轮探测中调用视图离屏绘制。离屏位图用于内存中的颜色/透明度统计，代码未将该位图保存为截图文件。

这不是“完全没有隐私影响”：窗口标题、界面结构和视觉统计可能揭示使用上下文；离屏绘制也会短暂接触当前输入法视图图像。其他调试日志并不全部受上述 8 轮限制。相关日志写入 LSPosed 日志，仍需按敏感诊断资料处理；不要公开原始日志、截图或设备备份。代码没有专门记录输入文字的逻辑，但这不代替安全审计，也不构成不泄露信息的保证。对敏感输入有要求时，不建议使用当前诊断版本。

`SettingsProvider` 以 exported provider 提供视觉配置/状态，其他应用可能读取这些信息。`debugHwWash` 是限 shell/root 的诊断开关：`0` 隐藏手写白底、`1` 保留原生白底，不是面向普通应用的设置入口。
